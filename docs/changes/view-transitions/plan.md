# 过渡生命周期实施计划

[English](plan.en.md) | 简体中文

状态：实施中。范围与职责由 [design](design.md) 定义。完成标准是公开接缝、可运行的应用自定义动画示例及必要组合验证，不以文档或内部类型数量计进度。

## 顺序与完成标准

| 阶段 | 交付与检查 | 风险 / ROI |
| --- | --- | --- |
| 1. 关键接缝 | 官方 UI/picking 小探针证明可见旧页不截断新页命中；拆稳定责任身份与删除 seal，保持立即路径行为 | 输入可行性先核验；生命周期配对风险高，属于必要基础 |
| 2. 退出责任 | request-scoped deferred owner、release/seal、父子 retain/dispose、未 seal 的 host loss；不预冻结可变化内容的删除清单 | 最高风险；完整退出动画所必需，独立交叉复核 |
| 3. 应用接入 | 发布前准备、已发布通知、受控展示表面、完成/取消、连续导航与过期通知处理；默认无驱动直通 | 中高风险；使实际应用可使用，避免仅内部绿测 |
| 4. 示例与收口 | 至少两种由应用定义的效果共用接口，覆盖 fresh/retained、Back、快速连续导航；同步合同/架构/指南 | 高 ROI；确认接口通用性和真实接线 |

初估约 6–10 人日，主要不确定性在 late-seal 与未 seal 的 authority settlement。先根据第 1 阶段证据修正后续工作量；不把上游补丁、现代 Android 手势、共享元素或整组透明度 renderer 纳入本次任务。

## 必要验证

- 默认关闭、等价导航保持原行为；新旧画面共存只有一个逻辑 active/history 发布点。
- 普通 `App::update` 证明发布前初始展示准备、已发布通知和应用完成/取消真实接通；enter 动画独立于 request terminal。
- 退出期间动态增删普通内容，结束后从原 owner 正确清理；父保留子清理、全 retained 与 Back 重新激活保持正确。
- 真实官方 picking：旧页可见仍拒绝事件，新页和其它有效目标正向命中，旧手势/focus 撤销，authored 属性不被覆盖。
- 连续请求按原顺序推进；旧动画先停止写入，过期完成不能结算新会话；host loss 保留已发布结果并结清原责任。
- enter-only 尚未结束就再次导航，以及初始展示准备后发布复验失败，均同步取消应用会话，目标复用前无旧写入。
- 复用访问级滚动旅程验证动画接入不改变 entry、ready/cancel 或实际恢复位置。
- 独立 consumer、窗口示例、相关 crate 与完整 public journey gate；效果观感用实际窗口证据，消息/几何检查不冒充渲染验收。

具体命令沿用[验证指南](../../development/verification.md)。共享 workspace 仅 root 运行 Cargo、管理 index 和提交；子代理按 Core、原生接线、应用示例的实际文件职责协作。

## 提交与文档

按“稳定责任/原行为重构 → deferred 退出协议 → 应用接线与输入 → 示例及合同”形成可审查批次。各批先完成对应验证；不把未接通的新 API 描述为已交付。

现行合同在行为落地后更新。设计只保留新增决策，不重复已有 ownership 协议；交付后必要语义归入专题合同与指南，完成计划退出默认文档树，由 Git 追溯。
